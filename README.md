# Personal Diary 🗒️

Веб-приложение личного дневника на Django: регистрация/логин по email, профиль пользователя и CRUD дневниковых записей (создание, просмотр, редактирование, удаление) с поиском и пагинацией.

---

## Возможности ✨

- Регистрация и вход по **email** (кастомная модель пользователя)
- Профиль пользователя: имя/фамилия/телефон/аватар/пол/дата рождения
- Дневниковые записи:
  - создание, просмотр, редактирование, удаление (только своих записей)
  - поиск по заголовку и тексту
  - пагинация
- UI на Django templates + Bootstrap
- Тесты на `unittest` (Django TestCase)

---

## Технологии 🧰

- Python 3.12
- Django 6.0.1
- PostgreSQL
- Redis
- Poetry 2.x
- Bootstrap (шаблоны)
- Pillow (аватарки)
- flake8, black, coverage

---

## Структура проекта 📁

- `users/` — кастомный пользователь, формы логина/регистрации/профиля, views, тесты
- `diary/` — дневниковые записи, формы, views, шаблоны, тесты
- `static/` — статические файлы (в т.ч. фоновые изображения карточек)
- `templates/` — базовые шаблоны + includes
- `config/` — настройки проекта и urls
- `docker-compose.yml`, `Dockerfile` — контейнеризация

## 🚀 Контейнеризация и CI
В проекте реализована контейнеризация и автоматизированный процесс Continuous Integration (CI) с использованием Docker, Docker Compose и GitHub Actions.

---

### 🐳 Контейнеризация проекта
Проект полностью контейнеризован с использованием Docker Compose. Каждый ключевой сервис вынесен в отдельный контейнер, что обеспечивает изоляцию, воспроизводимость окружения и удобство запуска проекта.

В проекте используются следующие сервисы:

- **Django (web)** — основной backend приложения
- **PostgreSQL (db)** — база данных
- **Redis** — in-memory хранилище (используется для кеширования и готово для расширения функциональности)

Каждый сервис запускается в собственном контейнере, что позволяет:
- изолировать зависимости,
- избежать проблем с локальным окружением,
- легко запускать проект одной командой,
- подготовить проект к дальнейшему масштабированию.

---

### 📦 Используемые файлы контейнеризации

- **Dockerfile** — сборка Docker-образа Django-приложения с использованием Poetry 2.x  
- **docker-compose.yml** — оркестрация всех сервисов (Django, PostgreSQL, Redis)  
- **.env** — переменные окружения (не хранится в репозитории)

Для сервисов PostgreSQL, Redis и Django настроены **healthcheck-и**, которые позволяют отслеживать их готовность и корректную работу.

## ▶️ Запуск проекта локально (Docker)

### 1️⃣ Клонирование репозитория

```bash
git clone https://github.com/ptanch/personal-diary-pt
cd personal_diary_pt
```

### 2️⃣ Создание `.env` файла

Создайте файл `.env` в корне проекта и заполните его, например, так:

```env
DEBUG=True
SECRET_KEY=django-secret-key

POSTGRES_DB=personal_diary
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres
DB_HOST=db
DB_PORT=5432

REDIS_HOST=redis
REDIS_PORT=6379
```

### 3️⃣ Запуск проекта
```bash
docker compose up -d --build
```

После успешного запуска:

- Django-приложение доступно по адресу:
http://127.0.0.1:8000/
- база данных PostgreSQL и Redis поднимаются автоматически,
- применяются миграции,
- healthcheck-и проверяют готовность сервисов.

Проверка состояния контейнеров `docker compose ps`.
В статусе контейнеров можно увидеть состояние `healthy/unhealthy`.

## 🔁 CI — Continuous Integration
В проекте настроен CI с использованием **GitHub Actions**.

CI workflow выполняет следующие шаги:
- установка зависимостей через **Poetry 2.x**,
- запуск линтинга (**flake8**),
- применение миграций,
- запуск тестов Django,
- проверка возможности сборки Docker-образа проекта.

CI запускается автоматически при:
- создании Pull Request в ветку **develop**,
- push в ветку **develop**.

Файл CI workflow:
```
.github/workflows/ci.yml
```

### 📌 Результат
Благодаря контейнеризации и CI:
- проект запускается одной командой,
- окружение полностью воспроизводимо,
- код автоматически проверяется тестами и линтингом,

## Как запустить проект локально (без Docker)

### 1️⃣ Клонировать репозиторий
```bash
git clone https://github.com/ptanch/personal-diary-pt
cd personal-diary-pt
```

### 2️⃣ Установить Poetry

Если Poetry ещё не установлен:
```bash
pip install poetry
```

Проверить версию:
```bash
poetry --version
```

Проект использует Poetry 2.x.

### 3️⃣ Установить зависимости
```bash
poetry install
```
Poetry автоматически создаст виртуальное окружение и установит все зависимости из `pyproject.toml`.

### 4️⃣ Создать файл .env

В корне проекта создайте файл `.env` и укажите переменные окружения (пример):
```
DEBUG=True
SECRET_KEY=django-secret-key

POSTGRES_DB=personal_diary
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres
DB_HOST=localhost
DB_PORT=5432

REDIS_HOST=localhost
REDIS_PORT=6379
```

При локальном запуске значения `DB_HOST` и `REDIS_HOST` обычно равны `localhost`.

### 5️⃣ Применить миграции
```bash
poetry run python manage.py migrate
```

### 6️⃣ Создать суперпользователя
```bash
poetry run python manage.py createsuperuser
```

### 7️⃣ Запустить Redis

Redis должен быть запущен локально (например, через Docker):
```bash
docker run -p 6379:6379 redis:7-alpine
```

### 8️⃣ Запустить сервер Django
```bash
poetry run python manage.py runserver
```


После запуска приложение будет доступно по адресу:
- http://127.0.0.1:8000/users/login/
- http://127.0.0.1:8000/diary/
